# SWIR OS System Edition — physical Live USB qualification evidence 0.1

## Scope

This package prepares the first **physical-hardware** qualification pass for the
already verified UEFI VM path:

`final image -> physical USB -> Live session -> dedicated empty disk -> source USB detached -> installed boot`

It adds privacy-minimized evidence collection and a fail-closed two-phase
verifier. It does **not** complete the physical-hardware roadmap gate and does
not change the project progress percentage by itself.

The existing disposable-VM gate remains authoritative for automated installer
safety. This document is only the physical qualification procedure and evidence
format.

## Safety boundary

The evidence tools are deliberately read-only:

- no formatting, partitioning, mounting, unmounting or package installation;
- no `sudo`, `pkexec` or other privilege escalation;
- no automatic installer invocation;
- no disk writes except an optional explicitly named JSON evidence output file;
- the output file is created with mode `0600`, `O_EXCL` and `O_NOFOLLOW` where
  supported, so an existing path or symlink is refused;
- serial values are never emitted; only `serialPresent=true/false` is recorded;
- hostnames, usernames, MAC addresses and DMI UUIDs are not collected.

The collector always emits:

- `physicalHardwareQualificationClaim=false`;
- `secureBootSupportClaim=false`;
- `legacyBiosSupportClaim=false`;
- `allPcCompatibilityClaim=false`.

A green CI result therefore means the evidence machinery is safe and
internally tested, **not** that physical hardware has already passed.

## Evidence collector

`system/e2e/collect-physical-live-usb-evidence.py` collects:

- UEFI/legacy-observed boot mode;
- observed Secure Boot state when readable, without turning it into a support
  claim;
- kernel and architecture;
- privacy-minimized DMI vendor/product/version;
- virtualization evidence;
- the root filesystem source;
- the parent block-device transport;
- Live root label (`SWIR_LIVE_ROOT`);
- a redacted block-device topology;
- an optional persistence-marker hash.

The default output is stdout. To create an evidence file:

```bash
python3 system/e2e/collect-physical-live-usb-evidence.py \
  --phase live \
  --output ~/swir-live-physical-evidence.json
```

The collector is intentionally useful without root. If the host does not expose
one of the read-only observations, that field remains unknown rather than being
invented.

## Two-phase sequence verifier

`system/e2e/verify-physical-live-usb-sequence.py` accepts one Live snapshot and
one installed-system snapshot. It fails closed unless all of the following are
true:

1. both evidence digests are valid;
2. the Live snapshot was collected in `live` phase;
3. the installed snapshot was collected in `installed` phase;
4. neither snapshot is virtualized;
5. both snapshots are on the currently tested UEFI path;
6. the Live root resolves to a USB parent device and label `SWIR_LIVE_ROOT`;
7. the installed root no longer resolves to USB;
8. both snapshots describe the same privacy-minimized hardware identity;
9. the installed snapshot is not older than the Live snapshot;
10. an identical persistence marker is visible before installation and after
    the detached-USB boot.

A passing result is named a **physical sequence candidate**, not a completed
hardware qualification.

## Physical test procedure

Use a dedicated test computer and a separate empty SSD/NVMe/HDD. Do not use an
everyday disk containing data that matters.

### 1. Prepare final USB media

Write the final SWIR raw image generated by `build-live-usb-img.sh` to a USB
device using the documented operator-controlled imaging step. Verify its
published SHA-256 before boot.

Boot the computer from that physical USB through UEFI firmware. Do not claim
Secure Boot or legacy BIOS support from this run.

### 2. Confirm Live behavior before touching the target disk

In the Live session:

- confirm the graphical SWIR session is usable;
- verify the intended internal test disk is clearly distinguishable from the
  source USB;
- leave the graphical installer idle and confirm no internal disk has been
  modified;
- run the existing installer **preview** path against the dedicated empty test
  disk;
- test the source-USB refusal path;
- test cancel and wrong-confirmation paths and confirm the target remains
  unchanged.

No automated test in this repository is allowed to choose or format the
operator's real disk.

### 3. Create a persistence marker on the running Live root

For a physical qualification run, create a unique random token at the fixed
path:

`/var/lib/swir/qualification/persistence-token`

This is an explicit operator action on the running Live root. The collector only
reads and hashes the marker; it never creates it.

Collect the Live evidence after the marker exists:

```bash
python3 system/e2e/collect-physical-live-usb-evidence.py \
  --phase live \
  --output ~/swir-live-physical-evidence.json
```

The expected Live candidate conditions are UEFI, non-virtual hardware, root
label `SWIR_LIVE_ROOT` and a USB parent transport.

### 4. Install only after explicit human confirmation

Use the graphical installer and select only the dedicated empty test disk.
Review the exact target identity and partition plan. Continue only after the
separate destructive confirmation screen identifies the same target.

The normal product safety rules still apply: source media is blocked, mounted
or read-only targets are blocked, cancellation before the first destructive
write must remain safe, and recovery cannot restore erased data without a
separate backup.

### 5. Detach source USB and boot the installed system

After installation:

1. power the machine off;
2. physically remove the source USB;
3. boot from the installed test disk;
4. verify the SWIR graphical session starts;
5. verify expected user data and the persistence marker are present;
6. collect installed evidence:

```bash
python3 system/e2e/collect-physical-live-usb-evidence.py \
  --phase installed \
  --output ~/swir-installed-physical-evidence.json
```

### 6. Verify evidence continuity

Run:

```bash
python3 system/e2e/verify-physical-live-usb-sequence.py \
  --live ~/swir-live-physical-evidence.json \
  --installed ~/swir-installed-physical-evidence.json
```

The verifier must pass before the sequence is considered reviewable physical
evidence.

## What still blocks the roadmap item

Even a passing two-phase evidence pair does **not** complete physical hardware
qualification by itself. Review must still cover:

- source-USB target refusal on the real machine;
- cancel and wrong-confirmation paths leaving the physical target unchanged;
- explicit human confirmation before the first destructive write;
- graphics, network, audio and basic suspend/resume behavior on the tested
  hardware;
- device/firmware reporting, including fwupd/LVFS where the hardware exposes it;
- clear recording of the exact tested hardware scope.

Secure Boot, legacy BIOS and broad "works on all PCs" support remain outside the
claim until separately implemented and tested.

## CI contract

`.github/workflows/system-physical-live-usb-evidence.yml` verifies:

- Python syntax;
- Live USB, virtualization-refusal and installed-boot fixtures;
- serial redaction;
- mode-0600 exclusive evidence output;
- evidence tamper rejection;
- persistence continuity rejection;
- source-USB-still-attached rejection;
- real hosted-runner read-only probe behavior;
- static absence of destructive disk or privilege-escalation commands.

The hosted runner is never promoted to physical-hardware evidence.
